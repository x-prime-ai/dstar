Executive summary

DSTAR turns a designed document into a durable review surface. A person or agent can propose a complete revision, reviewers can attach comments to exact text, and an owner explicitly decides which version becomes current.

The canonical artifact stays simple: one HTML document, optional CSS, and package-local assets. The Engine preserves history and validates every candidate; the Viewer makes that model understandable without exposing storage internals.

1. The problem

Documents created with agents often lose the connection between the rendered result, the feedback that shaped it, and the exact version a person approved. Chat transcripts capture intent but are poor review records. Source repositories capture bytes but ask every reviewer to understand developer workflows.

DSTAR keeps the document as the center of collaboration: agents propose, people comment, and owners decide.

4. Product principles

  1. The document is canonical. Review the same HTML and CSS that will be reopened later.
  2. Human intent stays explicit. Drafting, posting, resolving, and accepting are separate actions.
  3. Agents receive exact context. A selected range or focused comment is bound to one immutable revision.
  4. History remains portable. The package reopens without depending on a Git checkout or a hosted editor.

5. Example review

A reviewer selects a sentence and leaves a question. An agent reads that focused thread and returns either an editable reply draft or a linked revision proposal. The reviewer can keep discussing while the owner independently accepts or declines the proposed document.

Key distinction: accepting a proposal does not silently resolve its motivating comment. Conversation state and version state remain legible.
